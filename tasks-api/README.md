# tasks-api — REST API списка задач на Go

Учебный HTTP-сервис для создания, просмотра, обновления и удаления задач (to-do). Реализован **только на стандартной библиотеке Go**, без базы данных и внешних зависимостей.

## Требования

- Go **1.20+** (рекомендуется 1.21+).
- Терминал и, для ручных запросов, `curl` или Postman.
- Адрес сервера: `http://localhost:8080`.

## Запуск

Откройте терминал **в папке `tasks-api`**, где лежит `go.mod`, и выполните:

```bash
go run ./cmd/server
```

В консоли появится сообщение:

```text
server listening on http://localhost:8080
```

По умолчанию используется порт `8080`. Если он занят, можно указать другой порт: `PORT=18080 go run ./cmd/server` (Git Bash/Linux/macOS) или `$env:PORT="18080"; go run ./cmd/server` (PowerShell); в командах `curl` замените порт соответственно.

Сервер работает до остановки сочетанием **Ctrl+C**. Откройте **второй терминал** для запросов:

```bash
curl -i http://localhost:8080/health
```

Запуск на Windows аналогичен: используйте PowerShell или Git Bash. Примеры `curl` ниже написаны для Linux/macOS/Git Bash; в PowerShell удобно использовать `curl.exe` и аккуратно экранировать кавычки или применять `Invoke-RestMethod`.

## Модель задачи

```json
{
  "id": 1,
  "title": "Купить молоко",
  "done": false,
  "created_at": "2026-11-01T08:30:00Z"
}
```

- `id` — уникальное возрастающее целое число, генерируется сервером.
- `title` — обязательная непустая строка; пробелы по краям удаляются.
- `done` — логическое значение, при `POST` можно опустить (по умолчанию `false`); при `PUT` обязательно.
- `created_at` — дата создания в формате RFC3339/ISO8601 (UTC), заполняется сервером и не меняется при обновлении.

В `POST` и `PUT` клиент отправляет только `title` и `done`; поля `id`/`created_at` в запросе запрещены. При `PUT` заменяются оба пользовательских поля целиком, тогда как `id` и `created_at` сохраняются.

## Таблица эндпоинтов

| Метод | Путь | Назначение | Успех | Частые ошибки |
|---|---|---|---|---|
| GET | `/tasks` | Получить все задачи | `200 OK` | `405` при другом методе |
| POST | `/tasks` | Создать задачу | `201 Created` | `400` при плохом JSON/полях |
| GET | `/tasks/{id}` | Получить задачу по ID | `200 OK` | `400` при неверном ID, `404` если не найдена |
| PUT | `/tasks/{id}` | Полностью обновить задачу | `200 OK` | `400` при неверных данных, `404` если не найдена |
| DELETE | `/tasks/{id}` | Удалить задачу | `204 No Content` | `400` при неверном ID, `404` если не найдена |
| GET | `/health` | Проверить состояние сервера (PRO) | `200 OK` | `405` при другом методе |

При использовании неподдерживаемого метода сервер возвращает `405 Method Not Allowed` и заголовок `Allow` со списком методов. Неизвестный маршрут даёт `404` в JSON.

## Примеры curl

### 1. Посмотреть список задач

```bash
curl -i http://localhost:8080/tasks
```

HTTP `200`, JSON при пустом хранилище:

```json
[]
```

### 2. Создать задачу

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Купить молоко","done":false}'
```

HTTP `201`, заголовок `Location: /tasks/1`, тело (время зависит от момента запроса):

```json
{
  "id": 1,
  "title": "Купить молоко",
  "done": false,
  "created_at": "2026-11-01T08:30:00Z"
}
```

### 3. Получить одну задачу

```bash
curl -i http://localhost:8080/tasks/1
```

HTTP `200`, тело содержит задачу с `id = 1`.

### 4. Полностью обновить задачу

```bash
curl -i -X PUT http://localhost:8080/tasks/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"Купить хлеб","done":true}'
```

HTTP `200`, ответ:

```json
{
  "id": 1,
  "title": "Купить хлеб",
  "done": true,
  "created_at": "2026-11-01T08:30:00Z"
}
```

### 5. Удалить задачу

```bash
curl -i -X DELETE http://localhost:8080/tasks/1
```

HTTP `204 No Content`. **Тело отсутствует** по требованиям HTTP для ответа `204`; это единственное исключение из правила «ответ в JSON».

### 6. Пример ошибки

```bash
curl -i http://localhost:8080/tasks/999
```

HTTP `404`, ответ:

```json
{"error":"задача не найдена"}
```

Другие неправильные запросы и их ожидаемые ответы приведены в **[manual-tests.md](manual-tests.md)**. В нём для каждого из пяти эндпоинтов есть успешный и ошибочный сценарии.

## Формат ответов и ошибок

- `Content-Type: application/json` для всех ответов, включая ошибки (у `204` нет тела).
- Ошибки в едином формате `{"error":"сообщение"}`.
- `400 Bad Request` — неверный `id`, незаполненный `title`, неправильный тип поля, неизвестные JSON-поля, некорректный `Content-Type`, некорректный JSON, отсутствующий `done` при `PUT`.
- `404 Not Found` — неизвестная задача или маршрут.
- `405 Method Not Allowed` — запрещённый для данного пути метод.
- `500 Internal Server Error` — неожиданная ошибка внутренней операции, возвращается JSON.
- Для `POST`/`PUT` нужен `Content-Type: application/json` (возможно с `charset=utf-8`); предел тела запроса — 1 МиБ.

## Как работает приложение

1. `main.go` создаёт хранилище `memory.New()` и подключает его к `handlers.New(store)`.
2. `net/http` определяет нужный обработчик по пути запроса.
3. Обработчик проверяет HTTP-метод, `id`, JSON и обязательные поля.
4. Обработчик вызывает интерфейс `Storage`: `List`, `Create`, `Get`, `Update`, `Delete`.
5. In-memory хранилище использует `map[int]models.Task` и `sync.RWMutex`, поэтому параллельные запросы не вызывают гонки данных. При выдаче списка задачи сортируются по ID.
6. Сервер отправляет JSON-ответ и нужный HTTP-код. Middleware пишет в лог метод и путь запроса; неожиданные паники превращаются в ответ `500`.

```text
curl / Postman
      |
      v
  HTTP :8080
      |
      v
 logging + recover
      |
      v
  net/http mux
      |
      v
 handlers/tasks.go
   | проверка JSON и ID
      v
 Storage (интерфейс)
      |
      v
 memory.Store
   map + sync.RWMutex
```

**Важно:** хранилище находится в оперативной памяти. После перезапуска сервера все задачи исчезают, ID снова начинаются с 1. База данных не используется.

## Автоматические тесты

```bash
go test ./...
```

Дополнительная проверка на гонки данных (при поддержке `-race` установленной средой Go):

```bash
go test -race ./...
```

Тесты проверяют CRUD, HTTP-коды, заголовки, формат JSON, валидацию, неизменность `id`/`created_at`, ошибку 500, а также 200 конкурентных операций. Ручные тесты с `curl` описаны отдельно в `manual-tests.md`.
